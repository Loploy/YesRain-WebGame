# 개발 로그

## 2026-11-13

### 저장소 기본 세팅

**문제 / 목표**

- 사용자가 지정한 `Loploy/YesRain-WebGame` 저장소와 로컬 작업 폴더 연결.
- 메인 게임 프로토타입 작업 위치를 `webGame-prototype/`으로 지정.
- 게임 구현 전 Git과 공통 파일 설정 준비.

**원인 파악**

- 작업 시작 당시 로컬 Git 저장소가 없었음.
- GitHub Git refs 조회에서 빈 저장소 응답 확인.
- 로컬에는 `PLAN.md`와 빈 폴더 3개만 있었음.
- 기존 기획서는 현재 프로토타입 작업 위치를 `yesrain-web`으로 안내하고 있었음.

**해결 / 구현**

- Git 초기화, 지정한 `origin` 연결, `main` 최초 커밋·push 범위를 사용자 승인받음.
- `main` Git 저장소 초기화 및 지정한 `origin` 연결 완료.
- `.gitignore`, `.gitattributes`, `.editorconfig` 추가.
- 프로젝트별 작업 위치와 현재 개발 상태를 `AGENTS.md`에 기록.
- 프로젝트 안내, TODO, 개발 로그 추가.
- 기존 `PLAN.md`의 현재 프로토타입 작업 위치 수정.
- `webGame-prototype/.gitkeep`으로 빈 작업 위치를 Git에서 추적하도록 준비.
- 기존 폴더와 다운로드 폴더의 기획서 원본은 이동·삭제하지 않음.
- 게임 코드, 라이브러리, 배포 설정은 이번 범위에서 제외함.

**확인**

- Git `2.53.0.windows.1`, Node.js `v22.14.0`, npm `10.9.2` 설치 확인.
- `python -X utf8 -`로 파일 9개, UTF-8, 신규 파일 LF, EditorConfig 형식, 문서 내부 링크 점검 통과.
- 다운로드 폴더 원본과 비교하여 `PLAN.md`의 작업 위치 두 줄만 변경됨을 확인.
- `git check-ignore`로 의존성·빌드 결과·환경 변수·개인 IDE 설정 제외 확인.
- `.env.example`, `.env.development.example` 추적 가능 확인.
- `git check-attr`로 일반 텍스트 LF와 Windows 명령 파일 CRLF 속성 확인.
- 기존 `balance-calculator/`, `yesrain-web/`가 빈 폴더로 유지됨을 확인.
- 실제 게임 코드가 없어 빌드·게임 기능·브라우저 테스트는 실행하지 않음.

**원격 반영**

- 최초 커밋 `511e2f3` 생성. 메시지는 `chore: YesRain 프로젝트 기본 세팅`임.
- 첫 push는 GitHub 비공개 이메일 보호 오류 `GH007`로 거절됨.
- 사용자의 재시도 요청 후 기존 커밋으로 `git push -u origin main` 성공.
- 이메일 설정 변경과 커밋 재작성 없이 원격 반영 완료.
- `git ls-remote origin refs/heads/main`으로 원격 `main`과 로컬 최초 커밋 해시 일치 확인.
- `main`의 upstream이 `origin/main`으로 설정됨.

## 2026-11-14

### 로봇 공방 프로토타입과 사용자 미션 6종

**문제 / 목표**

- `webGame-prototype/`에서 조립·파견 게임을 플레이할 수 있는 첫 버전 제작.
- 사용자 `IDEA.md`와 사진에 적힌 상황을 미션으로 반영.
- 사용자가 중복 지급 방지를 질문함. 같은 파견의 재요청과 새 파견의 보상을 구분해 설명함.

**원인 파악**

- 기존 외부 프로토타입에서 부품·미션·특성 비교와 0·25·60코인 구조 확인.
- 기존 저장 복원은 부품 ID와 슬롯 검증이 부족해 손상 데이터에서 오류 가능성이 있었음.
- 최초 아이디어 파일은 저장 전 빈 파일이었음. 저장 이후 사진을 직접 열어 확인함.
- 처음 연결된 사진 두 장이 동일했음. 이후 사용자가 정리한 `docs/photo/`에서 6번 사진 추가 확인.
- 4번 문구를 잘못 읽은 뒤 원본을 확대해 아이의 하원 동행 상황으로 정정함.

**해결 / 구현**

- 승인한 `feat/game-prototype` 브랜치에서 작업.
- 외부 라이브러리 없이 HTML/CSS/JavaScript 사용.
- 게임 규칙은 `game.js`, DOM·입력·저장은 `app.js`로 분리함.
- 미션 6종과 부품 20종 추가. 각 미션에 게임용 요구 조건 4개 설정.
- 낮은 동굴 강아지 구조, 갯벌 휴대폰 회수, 건물 잔해 탐색, 아이 하원 동행, 수영장 반지 회수, 학생 교감 상황 반영.
- 장착 부품에 따라 몸통·장비·이동 장치 SVG 형태 변경.
- 거미형 다리와 광폭 무한궤도처럼 같은 조건을 충족하는 대안 허용.
- 부품 찾기는 미보유 부품 하나를 지급하는 테스트 보급 방식 사용.
- 일부 조건 충족은 25코인, 전체 충족은 60코인, 충족 없음은 0코인 지급.
- 완료한 파견은 보상 재지급하지 않음. 다른 의뢰를 선택하면 새 파견으로 시작함.
- 파견 당시 조립과 결과를 고정함. 다음 미션에서는 이전 보고서를 비움.
- 저장 데이터의 부품·슬롯·미션·잔액 형식 검증. 잘못된 값은 시작 상태로 복구함.
- 저장 실패 시 현재 창에서 플레이를 유지하고 하단에 실패 안내 표시.
- 기존 별도 프로토타입의 저장키와 사용자 아이디어·사진 원본은 변경하지 않음.
- 사용자가 직접 정리 중인 `docs/idea/`, `docs/photo/`는 기능 커밋 대상에서 제외함.

**코드 점검**

- `node --check webGame-prototype/game.js` 통과.
- `node --check webGame-prototype/app.js` 통과.
- `node --test webGame-prototype/game.test.cjs` 단위 테스트 18개 통과.
- 미션별 전체 충족 조합, 부분·미충족 보상, 갯벌 대안 조합 검사.
- 같은 파견 재요청, 저장 복원 후 재요청, 새 파견 보상, 부품 재사용 검사.
- 손상 저장값·잘못된 슬롯 복구와 미보유 부품 보급 종료 검사.
- 최초 샌드박스 실행은 테스트 러너 자식 프로세스의 `spawn EPERM`으로 실패함. 권한을 적용한 재실행에서 18개 통과.
- `python -X utf8 -`로 HTML ID 33개 중복 여부, 화면 리소스·DOM 참조·문서 링크, UTF-8/LF 검사 통과.
- `git diff --check` 통과.
- 브라우저와 모바일 화면을 열거나 실제 UI·localStorage 동작을 검수하지 않음.

**범위 및 남은 확인**

- 부품 특성과 미션 요구 조건은 게임용 임시값임.
- 음성 인식·대화는 부품 특성 판정으로 표현함. 실제 음성 입력이나 외부 AI 연동은 없음.
- QR, 로그인, 실물 지급, 실제 축제 잔액, 배포는 후속 범위임.
- 사용자 브라우저·모바일 검수 후 `main` 병합 여부 결정.
