**해결 / 구현**

- Git 초기화, 지정한 `origin` 연결, `main` 최초 커밋·push 범위를 사용자 승인받음.

- 기존 `PLAN.md`의 현재 프로토타입 작업 위치 수정.
- `webGame-prototype/.gitkeep`으로 빈 작업 위치를 Git에서 추적하도록 준비.
- 기존 폴더와 다운로드 폴더의 기획서 원본은 이동·삭제하지 않음.
- 게임 코드, 라이브러리, 배포 설정은 이번 범위에서 제외함.

**확인**

**해결 / 구현**

### 테스트 단계 전체 부품 지급과 데이터 관리 분리

**문제 / 목표**

- 사용자가 테스트 단계에서는 모든 부품을 제공하도록 요청함.
- 부품 목록을 한곳에 모으는 등 코드를 관리하기 쉽게 정리하도록 요청함.

**해결 / 구현**

- 기존 `feat/game-prototype` 브랜치에서 작업.
- 부품·미션·슬롯·초기 장착·시작 부품·전체 지급 설정을 `data.js`로 분리함.

- 브라우저는 `data.js` → `game.js` → `app.js` 순서로 로드함. Node.js도 같은 데이터 모듈 사용.
- `SETTINGS.unlockAllParts`를 `true`로 두고 새 시작 시 전체 목록을 지급함.
- 기존 저장 복원 시에도 전체 목록을 보충함. 코인·장착 부품·미션·완료 상태 유지.
- 부품 목록에 추가한 새 ID도 전체 지급에 자동 포함됨.
- 전체 보유 시 왼쪽 버튼은 `부품 목록`으로 표시하고 선택 창을 열도록 변경.
- 전체 지급을 끄면 시작 부품·기존 보유 목록·보급 수집 방식을 사용함. 이미 보유한 부품은 회수하지 않음.
- `docs/README.md`에 목록 수정 방법과 필드별 역할 기록.

### 미션 후보의 개수 제한 해제와 다양성 우선

- 사용자가 단계별 4개를 고정한 것이 아니며 후보를 더 많거나 적게 제시해도 된다고 정정함.
- 최대한 많은 아이디어와 검색을 통한 참신한 소재 발굴을 요청함.
- 지나치게 비슷한 미션을 피하고 다양하고 재미있는 후보를 우선하도록 요청함.
- `PLAN.md`와 TODO의 고정 개수 표현을 임시 기준으로 수정함.
- 후보 제안 단계이며 미션 확정이나 게임 코드 반영은 진행하지 않음.

### 센서와 특징적인 기능의 선택형 추가 부품 구상

- 사용자가 센서도 필요한 로봇에만 붙이는 추가 부품으로 생각하고 있다고 설명함.
- 온도 감지와 교감 로봇의 음성 인식을 핵심 기능 예시로 제시함.
- 센서·기능·특징적인 도구를 별도 탭으로 분류하는 구상을 기획서에 기록함.
- 기존 센서 제외 표현을 보완하고, 탭 이름·장착 수는 미정으로 구분함.
- `특수 장비`·`기능 모듈` 명칭과 등급 판단 방식은 AI 제안으로 표시함.
- 문서만 갱신함. 별도 장착 슬롯이나 실제 음성 인식 기능은 구현하지 않음.

### 특수 장비 장착 수와 감점 기준 검토

- 사용자가 무제한 장착과 불필요한 장비의 효율 감점을 검토함.
- 사소한 요소까지 고려해야 하는지 알기 어렵고 감점 기준이 애매하다는 우려 기록.
- 최대 n개 장착도 대안으로 검토 중이며 장착 수와 감점 여부는 미확정임.
- 최대 3개·무관한 장비 무가감점·설명에 근거가 있는 조건만 평가하는 방식은 AI 제안으로 구분함.
- 기획 문서와 TODO만 갱신함. 게임 코드 변경 없음.

### 특수 장비 임시 기준 채택과 재논의 시점

- 사용자가 최대 3개·무관한 장비 무가감점·빈칸 불이익 없음 제안을 임시 기준으로 채택함.
- 미션을 모두 확정하고 부품 구성이 어느 정도 정해지면 해당 내용을 다시 언급해 논의하도록 요청함.
- 기획서에 임시 채택 상태와 재논의 시점을 명시하고 TODO에 후속 알림 항목 기록.
- 이번 작업은 문서 기록만 진행함. 게임 코드에 장착 슬롯을 구현한 것은 아님.

### 등급 방향 정정과 간단한 로봇 구성 다양화

- 사용자가 등급은 낮은 숫자일수록 어렵고 3등급이 가장 쉽다고 정정함.
- 기존 AI 후보의 등급 방향이 반대였음을 인정하고 기획서에 정정 기준 기록.
- 간단한 등급 후보가 로봇 팔에 편중됐다는 사용자 지적 기록.
- 팔 외의 감지·급수·송풍·흡입·벨트 장치 활용은 AI 검토안으로 추가함.
- 기존 60개 후보를 확정된 미션·등급으로 취급하지 않음.

### 모든 부품의 다용도 재사용 기준

- 사용자가 화분 급수 예시의 물통은 해당 로봇만을 위한 전용 부품처럼 보인다고 지적함.
- 특정 로봇 전용 부품은 허용하지 않고 모든 부품이 다양한 로봇에서 쓰여야 한다는 기준 기록.
- 기획서·프로젝트 규칙에 재사용 기준을 반영하고 기존 후보 재검토를 TODO에 추가.
- 게임 코드나 기존 부품 목록은 이번 작업에서 변경하지 않음.
