# YesRain 응비제 웹 게임

## 프로젝트 개요

- NIVIS 응비제용 모바일 웹 게임 프로젝트임.
- 부품 수집 → 미션 확인 → 로봇 조립 → 파견 → 결과·코인 확인 흐름의 프로토타입임.
- 상세 기획은 [PLAN.md](../PLAN.md) 참고.

## 현재 상태

- 현재 메인 게임 프로토타입 작업 위치는 `webGame-prototype/`임.
- HTML/CSS/JavaScript로 구현. 외부 라이브러리 설치와 빌드 과정 없음.
- 부품 20종 전체 지급, 조립 미리보기, 미션 6종, 테스트 코인, 브라우저 저장 구현.
- 현재 테스트 단계에서는 처음부터 모든 부품 사용 가능함. 기존 저장을 불러와도 전체 부품을 보충함.
- 중앙 로봇과 플로팅 미션·보급·부품 슬롯·주요 행동 버튼으로 한 화면 게임 UI 구성.
- 부품 선택·미션 상세·출동 결과는 팝업으로 표시함.
- 실제 브라우저·모바일 화면과 조작은 사용자 검수 대기 중임.
- 배포 설정은 아직 없음.
- QR, 로그인, 실제 코인·인형 지급, 매점 결제는 후속 범위임.

## 시작 방법

- GitHub 저장소: [Loploy/YesRain-WebGame](https://github.com/Loploy/YesRain-WebGame)
- 새 작업 환경에서는 아래 명령으로 저장소를 가져옴.

```powershell
git clone https://github.com/Loploy/YesRain-WebGame.git yesrain-festival
cd yesrain-festival
```

- 현재 폴더에서는 다시 clone하지 않고 기존 폴더를 사용함.
- 게임 구현 전에 `PLAN.md`, `AGENTS.md`, `docs/todo.md`를 확인함.

## 프로토타입 실행

- [게임 파일](../webGame-prototype/index.html)을 브라우저로 열어 실행함.
- 진행 저장을 확인할 때는 같은 주소를 유지하는 로컬 서버 사용을 권장함.
- 저장은 해당 브라우저·접속 주소에만 적용됨. 파일 직접 열기의 저장 동작은 브라우저마다 다를 수 있음.
- Python이 설치된 현재 환경에서는 저장소 루트에서 아래 명령 실행.

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory webGame-prototype
```

- 브라우저에서 `http://127.0.0.1:8000` 접속.
- 종료 시 터미널에서 `Ctrl+C` 입력.
- 다른 포트·주소·브라우저에서는 별도 진행으로 취급됨.

## 플레이 방법

1. 상단 미션 버튼을 눌러 상세 내용을 보거나 다른 미션 선택.
2. 로봇 아래 몸통 / 팔·장비 / 이동 장치 슬롯을 눌러 부품 선택 창 열기.
3. 보유 부품을 누르면 장착하고 창을 닫음. 중앙 로봇과 상단 충족 조건에서 변화 확인.
4. 무대 왼쪽 `부품 목록` 버튼으로도 부품 선택 창을 열 수 있음. 현재 테스트 단계는 수집 없이 모든 부품 조합을 사용함.
5. 하단 `파견하기`를 누르면 출동 결과 팝업에서 충족·부족 조건과 코인 확인.
6. `다음 미션`으로 이동해 부품 재사용. 결과를 닫았으면 무대 오른쪽 `보고서` 버튼으로 다시 확인 가능함.

## 화면과 조작

- 화면 전체를 게임 무대로 사용하고 로봇을 중앙에 표시함.
- 주요 행동 버튼은 준비 중 `파견하기`, 출동 후 `다음 미션`으로 변경됨.
- 긴 미션·부품 목록은 팝업 안에서만 스크롤함.
- 부품을 고르면 팝업이 자동으로 닫힘. 닫기 버튼·바깥 영역·Escape로도 닫을 수 있음.
- 모바일 주소창과 화면 안전 영역을 고려해 `dvh`와 safe-area 여백 사용.
- 낮은 가로 화면에서는 부품 슬롯과 주요 행동 버튼을 오른쪽으로 옮김.
- 높이 480px 미만의 좁은 세로 화면에서는 조작이 잘리지 않도록 최소 높이와 세로 스크롤 예외 적용.
- 실제 기기에서의 한 화면 배치와 조작은 사용자 검수 필요.
- 상세 UI 기준은 [기획서의 화면과 조작 기준](../PLAN.md) 참고.

- 조건 0개 충족은 0코인, 일부 충족은 25코인, 전체 충족은 60코인 지급.
- 같은 파견의 지급 버튼을 다시 누르거나 완료 상태를 복원해도 추가 지급되지 않음.
- 새 의뢰는 새 파견으로 처리함. 반복 플레이로 테스트 코인을 받을 수 있음.
- 전체 지급 설정을 끈 수집 방식에서는 QR 대신 테스트 보급 버튼으로 미보유 부품을 얻음.
- 음성 인식·대화는 부품 특성으로 판정함. 실제 음성 입력이나 AI 대화 기능은 구현 범위에 포함하지 않음.
- 부품의 특성과 보상은 게임용 임시값임. 실제 로봇 성능이나 축제 보상 기준이 아님.
- 코인·소유 부품은 브라우저 저장값임. 실제 지급·결제나 계정 간 동기화에 사용하지 않음.

## 적용 미션과 예시 조합

| 미션 | 요구 조건 | 전체 충족 예시 |
| --- | --- | --- |
| 동굴 속 강아지 구조 | 낮은 차체, 좁은 통로, 조명, 안전 운반 | 낮은 로봇개 몸통 + 구조용 운반 받침대 + 자동차 바퀴 |
| 갯벌 휴대폰 회수 | 접지압 분산, 갯벌 이동, 정밀 집기, 방수 | 방수 몸통 + 휴머노이드 팔 + 거미형 다리 또는 광폭 무한궤도 |
| 건물 잔해 속 사람 탐색 | 비행, 장애물 감지, 열원 감지, 구조 신호 | 드론 몸통 + 구조 탐색 센서 + 비행 프로펠러 |
| 아이 하원 동행 | 직립 자세, 보행, 거리 감지, 균형 제어 | 휴머노이드 몸통 + 라이다 균형 장치 + 휴머노이드 다리 |
| 수영장 반지 회수 | 방수, 잠수 이동, 금속 탐지, 정밀 집기 | 방수 몸통 + 탐지 집게 + 수중 추진기 |
| 공부에 지친 학생과 교감 | 친근한 외형, 음성 인식, 대화, 조용한 이동 | 고양이 친구 몸통 + 듣고 말하는 대화 모듈 + 저소음 바퀴 |

- 사용자 아이디어의 상황 6개를 적용함. 조건별 특성과 조합은 프로토타입에서 조정 가능함.

## 부품과 미션 관리

- 목록과 설정은 [data.js](../webGame-prototype/data.js) 한곳에서 수정함.

| 항목 | 수정할 내용 |
| --- | --- |
| `SETTINGS.unlockAllParts` | `true`이면 새 시작·기존 저장 복원 시 전체 부품 지급. 현재 테스트 단계는 `true`임 |
| `PARTS` | 부품 ID와 장착 위치·이름·특성·색·그림 종류·설명 |
| `MISSIONS` | 미션 제목·상황·요구 조건·힌트 |
| `SLOTS` | 몸통 / 팔·장비 / 이동 장치의 슬롯 표시명 |
| `DEFAULT_EQUIPMENT` | 새 시작 시 장착할 부품 ID |
| `STARTER_PARTS` | 전체 지급을 끈 경우에만 사용하는 시작 부품 ID 목록 |

- `PARTS`는 몸통 / 팔·장비 / 이동 장치 순서로 모아 둠.
- 새 시작의 기본 미션은 `MISSIONS`의 첫 번째 항목임.
- 기본 장착 부품은 유효한 부품 ID를 사용함. 수집 방식에서는 `STARTER_PARTS`에도 포함해야 함.
- 기존 부품 ID는 저장 데이터와 연결됨. 새 부품은 새로운 ID로 추가함.
- `slot`은 `body`, `arm`, `base` 중 하나 사용.
- `traits`는 미션의 `needs`와 같은 문자열로 작성해야 조건이 충족됨.
- `type`은 `app.js`의 해당 슬롯 그림 종류와 연결됨. 기존 그림을 쓰는 부품은 같은 `type`을 사용함.
- 새로운 그림 종류를 만들 때만 `app.js`의 `drawBody`, `drawArm`, `drawBase`에 해당 형태를 추가함.
- `name`, `note`, `color`는 이름·설명·색상으로 화면에 반영됨.
- 전체 지급 상태에서는 목록에 추가한 부품도 자동으로 사용할 수 있음.
- `game.js`는 판정·지급·저장 복원, `app.js`는 화면·조작 담당. 목록 수정 때문에 게임 규칙을 바꿀 필요 없음.
- 전체 지급을 끄려면 `SETTINGS.unlockAllParts`를 `false`로 변경함. 기존 저장에 이미 지급한 부품은 회수하지 않음.

## 코드 점검

```powershell
node --check webGame-prototype/data.js
node --check webGame-prototype/game.js
node --check webGame-prototype/app.js
node --test webGame-prototype/game.test.cjs
```

- JavaScript 문법과 판정·저장 복원·중복 지급 방지 로직을 검사함.
- 브라우저 렌더링·실제 localStorage 동작·모바일 조작 검수를 대신하지 않음.

## 사용자 확인 항목

- 320×568, 390×844 등 세로 화면에서 페이지 스크롤 없이 미션·로봇·보급·부품 슬롯·파견 버튼을 볼 수 있는지 확인.
- 667×375 등 가로 화면에서 오른쪽 조작 버튼과 로봇이 겹치지 않는지 확인.
- 화면 회전·모바일 주소창 변화·노치 영역에서 버튼이 잘리지 않는지 확인.
- 미션 버튼과 부품 슬롯에서 팝업이 열리고, 부품 선택 후 닫히는지 확인.
- 팝업의 내부 스크롤·닫기 버튼·바깥 영역·Escape와 키보드 포커스 복귀 확인.
- 몸통·장비·이동 장치를 바꾸면 그림과 충족 조건이 함께 바뀌는지 확인.
- 예시 조합의 전체 보상과 조건 부족 조합의 부분 보상을 비교.
- 완료한 파견에서 버튼 연타 및 새로고침 후 잔액이 다시 늘지 않는지 확인.
- 새로고침 후 부품·조립·선택한 미션·코인·보고서가 유지되는지 확인.
- 새 시작·기존 저장 복원 모두 부품 20종이 보이고, 왼쪽 `부품 목록` 버튼을 누를 수 있는지 확인.
- 브라우저 저장이 차단된 환경에서는 하단 저장 실패 안내 확인.
- 기존 진행이 있는 같은 주소에서 UI 개편 후에도 부품·조립·미션·코인이 유지되는지 확인.

## 공통 설정

- 텍스트 인코딩은 UTF-8 사용.
- 기본 들여쓰기는 공백 2칸 사용.
- 저장소 텍스트 줄바꿈은 LF 사용. Windows 명령 파일은 CRLF 사용.
- 의존성, 빌드 결과, 로그, 개인 IDE 설정, 로컬 환경 변수는 Git 추적에서 제외함.
- `.env.example`, `.env.*.example`에는 실제 인증 정보를 넣지 않음.

## Git 작업 방식

- 최초 기본 세팅은 `main`에 기준 커밋으로 기록함.
- 후속 구현은 최신 `main`에서 작업별 브랜치를 만들어 진행함.
- 현재 프로토타입 구현 브랜치는 `feat/game-prototype`임.
- 사용자 실제 확인 전에는 `main` 병합과 배포를 진행하지 않음.
- 실제 구현 시작 전 작업 범위와 브랜치를 확인함.
- 브라우저 및 모바일 실제 기능 확인은 사용자 테스트로 구분함.
