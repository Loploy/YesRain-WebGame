# YesRain 응비제 웹 게임

## 프로젝트 개요

- NIVIS 응비제용 모바일 웹 게임 프로젝트임.
- 부품 수집 → 미션 확인 → 로봇 조립 → 파견 → 결과·코인 확인 흐름의 프로토타입임.
- 상세 기획은 [PLAN.md](../PLAN.md) 참고.

## 현재 상태

- 현재 메인 게임 프로토타입 작업 위치는 `webGame-prototype/`임.
- HTML/CSS/JavaScript로 구현. 외부 라이브러리 설치와 빌드 과정 없음.
- 부품 20종, 조립 미리보기, 미션 6종, 테스트 보급·코인, 브라우저 저장 구현.
- 실제 브라우저·모바일 화면과 조작은 사용자 검수 대기 중임.
- 배포 설정은 아직 없음.
- QR, 로그인, 실제 코인·인형 지급, 매점 결제는 후속 범위임.

## 시작 방법

- GitHub 저장소: [Loploy/YesRain-WebGame](https://github.com/Loploy/YesRain-WebGame)
- 새 작업 환경에서는 아래 명령으로 저장소를 가져옴.

```powershell
git clone https://github.com/Loploy/YesRain-WebGame.git yesrain-festival
cd yesrain-festival
```

- 현재 폴더에서는 다시 clone하지 않고 기존 폴더를 사용함.
- 게임 구현 전에 `PLAN.md`, `AGENTS.md`, `docs/todo.md`를 확인함.

## 프로토타입 실행

- [게임 파일](../webGame-prototype/index.html)을 브라우저로 열어 실행함.
- 진행 저장을 확인할 때는 같은 주소를 유지하는 로컬 서버 사용을 권장함.
- 저장은 해당 브라우저·접속 주소에만 적용됨. 파일 직접 열기의 저장 동작은 브라우저마다 다를 수 있음.
- Python이 설치된 현재 환경에서는 저장소 루트에서 아래 명령 실행.

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory webGame-prototype
```

- 브라우저에서 `http://127.0.0.1:8000` 접속.
- 종료 시 터미널에서 `Ctrl+C` 입력.
- 다른 포트·주소·브라우저에서는 별도 진행으로 취급됨.

## 플레이 방법

1. 의뢰 목록에서 미션 선택.
2. 몸통 / 팔·장비 / 이동 장치 탭에서 보유 부품 선택.
3. 로봇 미리보기와 충족 조건 확인.
4. 필요한 부품이 없으면 테스트 보급 상자로 미보유 부품 하나 획득.
5. 파견 후 보고서에서 충족·부족 조건과 코인 확인.
6. 다른 의뢰나 다음 의뢰를 선택해 부품 재사용.

- 조건 0개 충족은 0코인, 일부 충족은 25코인, 전체 충족은 60코인 지급.
- 같은 파견의 지급 버튼을 다시 누르거나 완료 상태를 복원해도 추가 지급되지 않음.
- 새 의뢰는 새 파견으로 처리함. 반복 플레이로 테스트 코인을 받을 수 있음.
- QR 수집 대신 테스트 보급 버튼을 사용함.
- 음성 인식·대화는 부품 특성으로 판정함. 실제 음성 입력이나 AI 대화 기능은 구현 범위에 포함하지 않음.
- 부품의 특성과 보상은 게임용 임시값임. 실제 로봇 성능이나 축제 보상 기준이 아님.
- 코인·소유 부품은 브라우저 저장값임. 실제 지급·결제나 계정 간 동기화에 사용하지 않음.

## 적용 미션과 예시 조합

| 미션 | 요구 조건 | 전체 충족 예시 |
| --- | --- | --- |
| 동굴 속 강아지 구조 | 낮은 차체, 좁은 통로, 조명, 안전 운반 | 낮은 로봇개 몸통 + 구조용 운반 받침대 + 자동차 바퀴 |
| 갯벌 휴대폰 회수 | 접지압 분산, 갯벌 이동, 정밀 집기, 방수 | 방수 몸통 + 휴머노이드 팔 + 거미형 다리 또는 광폭 무한궤도 |
| 건물 잔해 속 사람 탐색 | 비행, 장애물 감지, 열원 감지, 구조 신호 | 드론 몸통 + 구조 탐색 센서 + 비행 프로펠러 |
| 아이 하원 동행 | 직립 자세, 보행, 거리 감지, 균형 제어 | 휴머노이드 몸통 + 라이다 균형 장치 + 휴머노이드 다리 |
| 수영장 반지 회수 | 방수, 잠수 이동, 금속 탐지, 정밀 집기 | 방수 몸통 + 탐지 집게 + 수중 추진기 |
| 공부에 지친 학생과 교감 | 친근한 외형, 음성 인식, 대화, 조용한 이동 | 고양이 친구 몸통 + 듣고 말하는 대화 모듈 + 저소음 바퀴 |

- 사용자 아이디어의 상황 6개를 적용함. 조건별 특성과 조합은 프로토타입에서 조정 가능함.

## 코드 점검

```powershell
node --check webGame-prototype/game.js
node --check webGame-prototype/app.js
node --test webGame-prototype/game.test.cjs
```

- JavaScript 문법과 판정·저장 복원·중복 지급 방지 로직을 검사함.
- 브라우저 렌더링·실제 localStorage 동작·모바일 조작 검수를 대신하지 않음.

## 사용자 확인 항목

- 모바일 폭에서 의뢰 목록을 가로로 이동하고 부품 탭을 선택할 수 있는지 확인.
- 몸통·장비·이동 장치를 바꾸면 그림과 충족 조건이 함께 바뀌는지 확인.
- 예시 조합의 전체 보상과 조건 부족 조합의 부분 보상을 비교.
- 완료한 파견에서 버튼 연타 및 새로고침 후 잔액이 다시 늘지 않는지 확인.
- 새로고침 후 부품·조립·선택한 미션·코인·보고서가 유지되는지 확인.
- 보급 상자의 중복 없는 획득과 모든 부품 발견 후 종료 상태 확인.
- 브라우저 저장이 차단된 환경에서는 하단 저장 실패 안내 확인.

```text
yesrain-festival/

├── webGame-prototype/       # 현재 메인 게임 프로토타입 작업 위치
│   ├── index.html          # 게임 화면과 진입점
│   ├── styles.css          # 공방 화면과 반응형 배치
│   ├── game.js             # 부품·미션·판정·상태 전이

│   └── .gitkeep             # 초기 세팅 파일 유지
├── balance-calculator/      # 기존 빈 폴더. 현재 작업 대상 아님
├── yesrain-web/             # 기존 빈 폴더. 현재 작업 대상 아님

├── AGENTS.md                # 프로젝트 작업 규칙
├── .editorconfig            # 인코딩·들여쓰기 설정
```

- 여러 작업 영역이 있는 기존 구조를 유지함.
- 빌드 없는 정적 페이지 구조로 `webGame-prototype/` 안에서 코드를 관리함.
- 개인 아이디어·사진 폴더는 사용자 작업물로 별도 유지함.
- `balance-calculator/`, `yesrain-web/`는 비어 있어 Git으로 추적되지 않음.
- 새 clone에서는 추적 중인 파일과 폴더만 생성됨.

## 공통 설정

- 텍스트 인코딩은 UTF-8 사용.
- 기본 들여쓰기는 공백 2칸 사용.
- 저장소 텍스트 줄바꿈은 LF 사용. Windows 명령 파일은 CRLF 사용.
- 의존성, 빌드 결과, 로그, 개인 IDE 설정, 로컬 환경 변수는 Git 추적에서 제외함.
- `.env.example`, `.env.*.example`에는 실제 인증 정보를 넣지 않음.

## Git 작업 방식

- 최초 기본 세팅은 `main`에 기준 커밋으로 기록함.
- 후속 구현은 최신 `main`에서 작업별 브랜치를 만들어 진행함.
- 현재 프로토타입 구현 브랜치는 `feat/game-prototype`임.
- 사용자 실제 확인 전에는 `main` 병합과 배포를 진행하지 않음.
- 실제 구현 시작 전 작업 범위와 브랜치를 확인함.
- 브라우저 및 모바일 실제 기능 확인은 사용자 테스트로 구분함.
